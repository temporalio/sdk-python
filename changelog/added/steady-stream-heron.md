Add experimental `temporalio.client.StreamStore`, the base class of a Stream Store, and `temporalio.testing.MemoryStreamStore`, a Store that keeps its Streams in memory for tests and local runs. A Store gets the requests of `temporalio.api.streamservice.v1`, which have the Stream id, and the request id of each create and each append as `request_id`. A create returns only `created`, and the SDK gives the caller the ref with the name of the Store. A Stream has no close, and it expires when the Retention of its Store has passed since its create or its last append that wrote a batch.
Add experimental Streams for client and Activity code. `stream_config=StreamConfig(stores=[...])` of `Client.connect` gives a client its Stream Stores, and `Client.create_stream` and `Client.get_stream` return a `Stream` to append to, read and describe. A failed call raises `temporalio.exceptions.StreamError` with a `reason`. `max_record_bytes`, `max_batch_bytes` and `max_batch_records` of `StreamConfig` bound an append, and one over a limit fails before its Store gets it. A read of a Stream from `get_stream` needs `body_type=` or a `StreamRef` with a type argument, and raises `TypeError` with neither. `Stream.read` stops at the first page with no Record, so a read with no wait reads to the newest Record, and a read with a wait stops once no Record came within the wait. `temporalio.contrib.streams.current_producer` gives the Producer of an Activity attempt, and `as_producer` gives back one that code stored.
Add experimental Streams for Workflow code. `workflow.create_stream` and `workflow.get_stream` return a `Stream` to append to, read and describe on the Stream Stores of the Worker's client, and `Replayer(stream_config=...)` gives a replay its Stores. The SDK chooses the Store of each call before the call starts, also in a replay. It calls the `store_selector` only for a ref with no Store name, in Workflow code for each such call, also for a create and a describe, and again in a replay. So the selector must return the same Store for the same call, must not block or do I/O, and must be safe to call from more than one thread.
Add experimental Stream reads for Workflow code. `Stream.read`, `read_pages` and `read_page` of a Workflow `Stream` give the Records as they come, a replay reads them again from the Store, and `temporalio.workflow.StreamReplayError` in the failure exception types of a Worker or a Workflow fails the Workflow when the Store no longer has them. The Worker option `stream_read_time` sets how long the reads of a Workflow Task can wait, and a read with a wait gives a page with no Record at that limit.
Add experimental `temporalio.contrib.streams.BufferedAppender`, which batches the appends of one Stream in client and Activity code. `append` returns immediately, a batch waits at most `max_delay`, one write runs at a time, and `async with` or `flush()` writes what is left.
