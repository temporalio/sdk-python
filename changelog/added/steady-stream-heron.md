Add experimental `temporalio.client.StreamStore`, the base class of a Stream Store, and `temporalio.testing.MemoryStreamStore`, a Store that keeps its Streams in memory for tests and local runs. A Store gets the requests of `temporalio.api.streamservice.v1`, which have the Stream id, and the request id of each create and each append as `request_id`. A create returns only `created`, and the SDK gives the caller the ref with the name of the Store. A Stream has no close, and it expires when the Retention of its Store has passed since its create or its last append that wrote a batch.
Add experimental Streams for client and Activity code. `stream_config=StreamConfig(stores=[...])` of `Client.connect` gives a client its Stream Stores, and `Client.create_stream` and `Client.get_stream` return a `Stream` to append to, read and describe. A failed call raises `temporalio.exceptions.StreamError` with a `reason`. `max_record_bytes`, `max_batch_bytes` and `max_batch_records` of `StreamConfig` bound an append, and one over a limit fails before its Store gets it. A read of a Stream from `get_stream` needs `body_type=` or a `StreamRef` with a type argument, and raises `TypeError` with neither. `Stream.read` and `read_pages` never end at a page with no Record and read again, so the caller decides when to stop, for example with a `break`. With no `wait`, the first read of an iterator gives the answer of the Store at once, and each later read waits up to 1 minute, so an iterator on an idle Stream doesn't call its Store in a loop. A `wait` that the caller gives holds for each read, and a `wait` of zero is no wait at all. `read_page` has no default wait. The wait of a read ends shortly before its `rpc_timeout`, so that the Store can answer in time. `temporalio.contrib.streams.current_producer` gives the Producer of an Activity attempt, and `as_producer` gives back one that code stored.
Add experimental Streams for Workflow code. `workflow.create_stream` and `workflow.get_stream` return a `Stream` to append to, read and describe on the Stream Stores of the Worker's client, and `Replayer(stream_config=...)` gives a replay its Stores. The SDK chooses the Store of each call before the call starts, also in a replay. It calls the `store_selector` only for a ref with no Store name, in Workflow code for each such call, also for a create and a describe, and again in a replay. So the selector must return the same Store for the same call, must not block or do I/O, and must be safe to call from more than one thread. SDK Core fails a replay with a nondeterminism error when a replayed append or read goes to another Store than the one in History.
Add experimental Stream reads for Workflow code. `Stream.read`, `read_pages` and `read_page` of a Workflow `Stream` give the Records as they come, a replay reads them again from the Store, and `temporalio.workflow.StreamReplayError` in the failure exception types of a Worker or a Workflow fails the Workflow when the Store no longer has them. The Worker option `stream_read_time` sets how long the reads of a Workflow Task can wait, and a read with a wait gives a page with no Record at that limit. In Workflow code, `read` and `read_pages` never end at a page with no Record and read again, also in later Workflow Tasks, so Workflow code decides when to stop. Each page is a read result in History. With the default wait of 1 minute, an iterator on an idle Stream gets few pages with no Record and makes no new Workflow Task, and with a `wait` of zero it reads again at once. A read with no wait gives the answer of the Store, which can be a page with no Record, and an outage of the Store at a read fails the Workflow Task.
Add experimental `temporalio.contrib.streams.BufferedAppender`, which batches the appends of one Stream in client and Activity code. `append` returns immediately, a batch waits at most `max_delay`, one write runs at a time, and `async with` or `flush()` writes what is left.
