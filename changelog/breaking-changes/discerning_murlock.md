External storage reference payloads are now encoded with the configured payload codec and marked with `__temporal_external_storage_reference` metadata, so claim data such as bucket names and object keys no longer reaches workflow history in plain text. References written by earlier versions are still read. Workers on earlier SDK versions cannot read encoded references, so if a codec is configured, a workflow processed by a worker on this version must not then be processed by a worker on an earlier version (for example, after a rollback or during a mixed-version deployment). Without a codec, references are not encoded and remain readable by earlier versions.
