The built-in `__temporal_workflow_metadata` query now encodes its result with the default payload converter and returns it as a `RawValue`, so the UI and CLI can read workflow metadata even when the worker's payload converter cannot serialize protobuf; the payload codec still applies. Custom payload converters must pass `RawValue` payloads through unchanged, as `PayloadConverter.to_payloads` documents; converters built on `CompositePayloadConverter`, including `DefaultPayloadConverter` and the Pydantic converter, already do.
